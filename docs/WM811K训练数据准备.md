# WM-811K 训练数据准备

当前步骤生成训练输入和固定划分，不训练模型、不报告模型准确率。原始 `LSWMD.pkl` 保持不变。

## 本机运行

电脑只有 16 GB 内存。先停止 Android 模拟器并关闭 Android Studio，再在 `E:\WaferAI\backend` 的命令窗口执行：

```bat
.venv\Scripts\python.exe scripts\prepare_wm811k.py
```

脚本需要读取完整 pickle；不是分块读取原始文件。随后只保留有标签的记录引用，释放未标注记录。标准化矩阵逐张写入磁盘映射数组，不把整个训练集展开为浮点张量。训练数据默认保存到 `E:\WaferAI\data\processed\wm811k-v1`。

已有输出目录不会覆盖，避免训练后意外改变划分。确需另做实验时使用新的 `--output` 目录。异常中断留下的 `.partial-*` 目录不是已完成的数据集；只有最终目录内 `preparation.json` 的 `complete: true` 才表示完成。

## 标签和清洗规则

固定类别顺序：`none, Center, Donut, Edge-Loc, Edge-Ring, Loc, Random, Scratch, Near-full`。

空标签 `[]` 排除；`none` 保留为一个类别，表示数据集未标注特定缺陷模式，不代表所有芯片都合格。0 为非芯片区域，1 为合格，2 为不合格。App 良率继续由原始矩阵计算，不能使用缩放后的训练输入计算良率。

非整数、非二维、包含非法编码、没有有效芯片或缺少批次标识的记录会排除并记录原因。未知缺陷类别直接报错，防止默默修改类别定义。原有标签可能存在主观或错误标注，脚本不能保证标注准确。

训练输入采用保持宽高比的最近邻缩放，居中补 0，生成 64×64 的 uint8 矩阵。后续模型将编码为 3 个 one-hot 通道。缩放可能损失小缺陷信息，这是首版 CNN 的工程取舍。

按最终 64×64 输入进行 SHA-256 去重，确保相同模型输入不会跨组：相同输入且标签一致时保留原始顺序第一条；相同输入却有多个标签时全部排除。冲突可能来自原始标注，也可能来自缩放丢失信息，不能一概断言为原始标注错误。每条候选同时保留原始矩阵 SHA-256，便于追溯。清洗会减少样本并改变类别比例，必须在论文中如实报告清洗前后数量。

## 数据划分与不均衡

使用 scikit-learn 的 StratifiedGroupKFold，以 `lotName` 为分组生成 7 折，随机种子固定为 42。取其中 1 折作为验证集、1 折作为测试集，其余 5 折作为训练集，比例约 71.4% / 14.3% / 14.3%，受批次大小影响不会严格相等。

验证折和测试折的选择只依据类别数量接近目标比例及三组都有九类，不使用模型效果。每类清洗后至少需要三个不同批次，否则停止；不自动退回逐张随机划分。程序校验批次互不重叠，输入也已全局去重。

原始 `trianTestLabel` 保存在清单中。本项目使用新的批次划分，不能把它的结果直接当作原始官方划分的评测结果。固定划分后，调参与早停仅使用验证集；模型和超参数确定后再执行最终测试，不反复用测试集选择模型。

准备阶段不做增强、重采样或类别平衡。后续只依据训练集计数设置类别权重，增强也只对训练集应用。验证集和测试集保持清洗后自然类别分布。严重不均衡时需要报告 macro-F1、每类 precision/recall/F1、混淆矩阵及各类样本数，不能只展示整体 accuracy。

## 输出

- `maps.npy`：N×64×64、uint8，只含清洗后保留的数据。
- `labels.npy`：N 个 int64 类别编号，顺序与 `maps.npy` 一致。
- `splits.npz`：train、validation、test 三个索引数组。
- `manifest.csv`：保留样本的原始行号、批次、晶圆编号、标签、哈希、处理后索引和所属组。
- `audit.csv`：全部有标签候选及其保留/排除原因。
- `preparation.json`：原始文件哈希、软件版本、清洗前后各类数量、划分数量、批次覆盖和输出文件哈希。
