# 手机连接与服务设置

Android 1.1 已支持保存分析服务地址。晶圆数据库、原始矩阵和 CNN 模型继续保存在电脑，手机通过服务读取和识别；当前版本的 CNN 不在手机上离线运行。

## App 内设置

1. 打开首页右上角“服务设置”。
2. 选择“模拟器连接”或“USB 连接”，也可以填写电脑服务地址。
3. 点击“检查并保存”，等待结果。只有返回兼容的 WaferAI 健康响应才会替换当前地址，验证最长约 8 秒。
4. 返回首页，从“历史记录”打开晶圆，或选择 JSON 文件导入。

只填写根地址，例如 `http://192.168.1.10:8000/`，不加 `/docs`、`/api`、查询参数或账号密码。App 自动补齐末尾斜杠。无效或无法连接的地址不会覆盖原设置，也不会清除正在查看的晶圆。

成功切换地址会清空当前页面及列表缓存，并取消旧服务的未完成页面请求，避免两个服务出现相同记录编号时误用旧数据。电脑上的数据不会被删除。仅重新检查相同地址时不清空当前晶圆。

## USB 手机：当前电脑的操作步骤

1. 先确认电脑服务已经运行。在电脑浏览器打开 `http://127.0.0.1:8000/api/v1/health`，应显示 `status: ok` 和 `service: WaferAI`。未运行时双击 `E:\WaferAI\backend\start-backend.bat`，保留窗口；已经运行时无需重复启动。
2. 用支持数据传输的 USB 线连接手机和电脑。在手机开发者选项启用 USB 调试，并由你在手机上确认允许这台电脑。具体系统入口可能随手机而不同；调试授权要求见 [Android 官方说明](https://developer.android.com/tools/adb#Enabling)。
3. 双击 `E:\WaferAI\backend\连接手机.bat`。工具检查真实 USB 手机及电脑服务，安装项目当前的 debug APK，设置手机端口到电脑服务的连接，并打开 WaferAI。它使用安装覆盖方式保留应用数据，不卸载原 App。
4. 手机 App 打开“服务设置”→“USB 连接”→“检查并保存”。地址应为 `http://127.0.0.1:8000/`。
5. 返回首页，进入“历史记录”。使用当前电脑已有数据时，可打开 `WM811K-lot2 / W20`，查看晶圆图和已保存的 Center 识别结果。
6. 保持电脑服务和数据线连接。拔插数据线、手机重启等情况可能使端口连接失效，再次运行“连接手机.bat”即可重新准备连接。

工具不会启用手机开发者选项，也不会代替你确认调试授权。没有真实手机、手机未授权或存在多台 USB 手机时，工具会给出提示，不自动选择模拟器。需要指定某台手机时，可在 `backend` 目录执行：

```bat
.venv\Scripts\python.exe scripts\connect_phone.py --serial 手机序列号 --install
```

仅检查手机和电脑服务、不安装也不修改端口连接：

```bat
.venv\Scripts\python.exe scripts\connect_phone.py --check
```

工具从本项目 Android SDK 设置或环境变量查找 adb，检查服务身份，设置 `adb reverse --no-rebind tcp:8000 tcp:8000`。若手机 8000 端口已映射到其他端口，会提示检查，不覆盖该连接。

## Wi-Fi 手机：可选方式

1. 手机与电脑连接同一局域网。
2. 若普通后端服务正运行，先在它的窗口按 Ctrl+C 停止。再双击 `E:\WaferAI\backend\start-backend-lan.bat`，它监听电脑的 8000 端口。
3. 在电脑命令提示符执行 `ipconfig`，查找正在使用的 Wi-Fi 或以太网连接的 IPv4 地址。例如地址为 `192.168.1.10` 时，在手机 App 填写 `http://192.168.1.10:8000/`。`0.0.0.0` 是服务监听配置，不能作为手机访问地址。
4. 先在手机浏览器打开该地址加 `/api/v1/health`。若打不开，检查是否同一网络、网络是否隔离设备，以及 Windows 是否允许该服务在当前专用网络接收连接。无需关闭整个防火墙。
5. 浏览器可访问后，回到 App“服务设置”，填写根地址，点击“检查并保存”。

局域网入口用于本地演示；默认启动入口仍为本机访问。当前仅 debug 构建允许本地 HTTP，未增加忽略 HTTPS 证书校验的逻辑。Android 的明文连接规则见 [官方网络安全配置文档](https://developer.android.com/privacy-and-security/security-config)。

## 已验证与待验证

服务设置功能在 Android Pixel_2 模拟器完成以下检查：

- 地址格式与服务身份的新增 8 项单元测试通过，连同原有基础测试共 9 项。
- debug 构建、覆盖安装成功；服务地址在升级并重启 App 后保留。
- 错误地址显示连接失败或超时，原服务及当前晶圆的 Center 结果保留。
- 使用模拟器上的 adb reverse 通道验证 USB 预设地址，成功切换后当前晶圆清空；重新打开历史记录可读取对应晶圆和已有识别结果。
- 去掉该测试通道后，设置页与首页均显示连接失败原因；旧的成功提示不会和错误提示同时保留。
- 已恢复模拟器默认地址；测试创建的临时端口连接已移除。

真实手机尚未接入，尚未完成实际手机安装、USB 稳定性或 Wi-Fi 联调。当前仅检测到模拟器时，手机工具正确提示连接和授权步骤。模拟器上的端口通道验证不能代替真机验收。此轮未重新训练模型或更改既有独立测试指标。
