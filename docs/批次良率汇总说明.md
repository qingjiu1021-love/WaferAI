# 批次良率汇总

首页点击“批次汇总”，查看各批次已导入并保存的晶圆数量、合格与不合格芯片合计、有效芯片总数及总体良率。点击批次可打开“批次晶圆”，查看汇总和对应晶圆列表；再点击晶圆可恢复原始矩阵及已有识别结果。

统计范围仅为当前后端已保存的数据。下载完整 WM-811K、完成模型训练，不代表全部原始晶圆已经导入业务数据库。当前两个批次各保存一张演示晶圆。

## 计算口径

总体良率 = 该批次所有已保存晶圆的合格芯片数之和 ÷ 有效芯片数之和。

有效芯片数 = 合格芯片数 + 不合格芯片数；编码 0 的非芯片区域不参与分母。不同晶圆芯片数可能不同，不能直接平均各张良率。例如，一张有 1 个合格芯片，另一张有 9 个不合格芯片，总体良率为 10%，不是 50%。

没有有效芯片时接口返回 `null`，页面显示“暂无”。批次按照数据库的 `(source, lot_code)` 关系区分。重复导入同一晶圆不重复计数，识别次数和模型版本不影响芯片统计。

## 接口和实现

- `GET /api/v1/lots?limit=20&offset=0`：批次列表，每页最多 100 个，默认 20 个。
- `GET /api/v1/lots/{lot_id}`：单个批次的完整汇总。
- `GET /api/v1/wafers?lot_id={lot_id}&limit=20&offset=0`：该批次晶圆列表。

列表按最后导入时间倒序排列，再按批次编号倒序排列。不存在的批次返回 `404 LOT_NOT_FOUND`，无效分页或批次参数返回 422。

批次响应字段包括 `id`、`source`、`lot_code`、`wafer_count`、`good_count`、`bad_count`、`total_count`、`yield_rate` 和 `last_imported_at`。良率为 0～1 的比值，页面显示为百分数。

SQLite 直接聚合已保存的芯片数量，不读取 NPY 矩阵，不关联预测历史，避免重复计数。汇总覆盖整个批次，不受当前页面加载数量影响。SQLite 使用 64 位整数累加；Android 芯片合计使用 `Long`，避免超过 32 位整数范围后溢出。本次没有新增表、迁移或依赖。
